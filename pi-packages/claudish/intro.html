plain-english rewrite · display-only · fails open

Every assistant reply gets a plain-English shadow.

claudish watches each message the agent finishes, asks a model to restate it in simple language, and tacks the result underneath — without changing a byte of the original. The rewrite is a custom session entry that renders in your TUI but never enters the model's context. What you see is glossed; what the model sees is not.

Every hook is wrapped so that on any rejection path — provider unreachable, request exceeding displayTimeoutMs, an empty response, a stop_reason of max_tokens, or the kill-switch flag file present on disk — the extension resolves {ok:false} and the caller short-circuits before any mutation, leaving the original message and transcript entry byte-identical. The once-per-session notice surfaces the first skip via ctx.ui.notify at warning level; subsequent failures in the same session stay silent.

sequence · the display hook

One message, eight beats — none of them block the agent.

When message_end fires, claudish runs entirely in the background: it guards, resolves the model and provider, calls out, and appends a custom entry. The stream and the agent loop keep moving the whole time. Step through it.

  1. message_end firespi → claudish · once per finalized assistant message
  2. guardsskip errors, tool-only msgs, prose < minChars
  3. find last user questioncontext for the rewriter — never answered
  4. resolve runtimeprovider · model · apiKey, from config or session model
  5. POST the promptbuildPrompt + timeout-guarded fetch to the provider
  6. rewrite returnsplain text, or { ok:false } on any problem
  7. appendEntrycustom "claudish-rewrite" entry added to the session
  8. render the ghostregisterEntryRenderer draws 💬 — invisible to the model

decision · fail-open

Every broken path lands in the same safe place.

The whole extension is built so it can never swallow or corrupt an answer. Six things can go wrong on a single rewrite; all six converge on one outcome — your original text, byte-identical, plus at most one notice.

Note: a rewrite that hits the maxTokens output cap is discarded, not shown — a half-finished plain-English version is confusing, and in overwrite mode it would have replaced a real document.

topology · provider routing

Zero-config: it rewrites through the model you're already using.

Leave provider and model out of the config and claudish follows your session. Auth is never stored in config — it's pulled from pi's model registry, the same key pi already uses.

Privacy: selecting a cloud provider is the consent switch. Auth comes from pi's registry, so if pi has a key for anthropic or openai, claudish will use it — and each assistant message leaves your machine. The default (follow session model) adds no new egress.

structure · the four files

Small surface, clear seams.

Hooks and rendering live in index.ts. Everything else is pure and independently testable — config parsing, the provider calls, and the text helpers. That separation is why 47 tests cover it cleanly.

Solid arrows are runtime calls from index.ts. The dashed arrow is a build-time import (providers.ts pulls types and MAX_INPUT_CHARS from config.ts). json-file.ts only ships describeError into config.ts; the md-hook's atomic write is local to index.ts.

comparison · two hooks

One rewrites your chat. The other rewrites your files.

claudish registers on two pi events. The chat hook is cosmetic and on by default; the file hook mutates disk and is strictly opt-in.

Why no "replace" mode for chat? Pi's transcript is the display — there's no separate presentation layer. Suppressing the original on screen would also rewrite what's stored and sent to the model. So the chat hook is always append-style; the model always sees the real text.

reference · control surface

One JSON file. One slash command. One flag file.

No environment variables. Config lives at <agentDir>/claudish.json, read at session start and on /reload. All fields optional — an empty {} uses every default.
